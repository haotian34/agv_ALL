# 单站点三平面视觉标定设计

日期：2026-11-18
状态：已获用户口头同意设计范围，待用户审阅书面设计

## 1. 背景与已确认决策

本阶段把整体任务收敛为单站点、单视野版本，接受仓库一次拍照不能覆盖整行。仓库与加工区各使用一个 AGV 停车区域，不设计第二站点及站点补偿。

- 仓库上两行原件：空夹爪视觉定位抓取，共两套平面标定；两行采用相同拍照 RPY，分别绑定自己的平面几何。
- 加工区加工件：空夹爪视觉定位抓取，共一套平面标定；拍照 RPY 与仓库不同。
- 仓库成品行：逐槽传感器选择空位，槽位编号映射预示教放置位姿；不使用 YOLO 找空位，不做视觉平面标定。
- 车上原件位和加工件位：与机械臂底座刚性固定，采用预示教取放位姿或轨迹，不做视觉平面标定。
- 加工区未加工原件放置：采用现场示教位姿，不做本阶段视觉标定。
- 实际抓取、放置 Z 下降量按作业面和动作分别示教，不从替代 A4 标定面的绝对高度获得。
- 传感器通信、加工完成握手、YOLO 训练和自动任务调度暂不阻塞本阶段。

因此，本阶段只建设三套视觉平面标定及静态定位验证能力，不实施自动运动或实抓。

## 2. 目标与非目标

### 目标

1. 用 A4 纸上的多个十字点建立“像素到标准拍照 TCP 下相对位置”的映射。
2. 同一程序分别生成 `warehouse_raw_1`、`warehouse_raw_2`、`machine_finished_pick` 三个独立配置。
3. 替代平面的绝对高度不必等于真实仓库或加工区，但最终配置必须绑定固定拍照 RPY、相对工作距离、图像分辨率和 toolcoord2。
4. 输入当前标准拍照 TCP 与目标像素，输出当前机械臂基座下的目标 XY；平面 Z 仅作几何诊断，最终运动 Z 仍取现场示教值。
5. 原始图像、像素、TCP 和中间过程增量保存，允许崩溃恢复，适应现场难以复现的限制。
6. 新脚本只读取相机和 TCP，不发送机械臂、底盘或夹爪运动命令，不覆盖旧手眼文件。

### 非目标

- 不根据标定残差直接允许自动抓取。
- 不实现 PLC/传感器通信、自动槽位调度或加工完成握手。
- 不实现 YOLO 训练或自动任务状态机。
- 不在本阶段示教真实仓库、加工区和车上取放轨迹。

## 3. 坐标定义与可复用原则

标准拍照 TCP 位姿记为 `P_photo=(t_photo,R_photo)`，全程使用 toolcoord2。标定结果不保存成某个替代面的绝对基座坐标，而保存目标在 `P_photo` 局部坐标系中的关系。

对第 i 个示教点，其基座坐标为 `p_i`：

```text
q_i = R_photo^T @ (p_i - t_photo)
```

像素映射学习 `(u,v) -> (q_x,q_y)`。因此运行时即使当前标准拍照 TCP 的平移不同，只要该配置要求的 RPY、相对工作距离、工具坐标和相机设置一致，就可重新计算当前基座下的目标：

```text
q = [q_x, q_y, q_z]
p_target = t_current + R_current @ q
```

相同高度不是唯一复用条件。若 RPY、工作距离、分辨率或工具坐标改变，必须重新标定或明确建立新的映射，不能直接混用配置。

## 4. 标定点与采集流程

每个平面使用 3×3 共九个编号十字点：外圈八点用于初始拟合，中心点用于独立几何检查。九点的图像和示教数据均保留。

1. 将 A4 纸平整固定在硬板上，采集和示教期间不得移动。
2. 机械臂由用户手动进入该配置的标准拍照位，脚本读取 `P_photo` 并保存一张静态彩色图。
3. 用户按编号点击九个十字中心；支持撤销和重新点选。
4. 图像采集完成后，用户通过 WebApp 手动低速移动机械臂，依次将 toolcoord2 的 TCP 对准每个实体十字中心。脚本只在用户确认后读取 TCP，不驱动运动。
5. 每完成一个像素点或 TCP 点立即追加写入会话文件，保存时间戳和顺序。
6. 九点齐全后先检查退化、重复点和初始残差，再计算中心点预测误差。检查未通过时保留原始会话，不生成可用配置。
7. 中心检查满足现场设定门限后，用全部九点重新拟合最终映射，同时保留“仅用外圈八点预测中心”的独立检查指标。

向日葵远控下只允许在机械臂完全停稳后点击或读取 TCP，不以远程画面作为运动安全监护。

## 5. 数学求解与输出

### 5.1 像素到局部 XY

采用带归一化的单应矩阵拟合：

```text
[q_x, q_y, 1]^T ~ H @ [u, v, 1]^T
```

至少四个不共线点才可求解，本设计使用八点初始拟合、九点最终拟合。输出 X/Y 残差 RMS、最大误差及最大误差点编号。

### 5.2 局部平面

利用示教 TCP 点拟合：

```text
q_z = a*q_x + b*q_y + c
```

运行时将像素换算为 `q_x,q_y`，再用平面方程补足 `q_z`。这样仓库与加工区可采用不同标准拍照 RPY，而不必假设所有平面都与 TCP XY 平行。

### 5.3 运行时定位

静态定位工具读取当前 TCP，检查当前 RPY 与配置标准 RPY 的角度差。输出：

- 当前基座目标 XY；
- 由相对平面几何得到的诊断 Z；
- 使用的配置 ID、图像尺寸和源数据版本；
- RPY 或图像尺寸不一致时的明确拒绝信息。

诊断 Z 不自动写入抓取目标，不替代现场 Z 示教。仅凭 TCP 无法在所有新站点自动证明相机到平面的工作距离正确，因此标准拍照位的恢复和现场静态验证仍是必要步骤。

## 6. 文件与组件

新增文件集中在 `现场调试脚本`，旧 `handeye_*` 文件保持不变。

- `plane_math.py`：纯数学计算，包含位姿转换、单应拟合、局部平面拟合、中心检查和运行时定位；不导入设备 SDK。
- `plane_calibrate.py`：RealSense 彩色图采集、像素点选、逐点 TCP 读取、断点恢复和配置生成。
- `plane_locate.py`：加载指定配置，读取当前 TCP 和目标像素，执行静态定位验证。
- `plane_profiles.json`：三个配置 ID、配置文件路径、标准拍照说明和现场 Z 参数占位；不把占位值当成可运动参数。
- `plane_sessions/`：原始图像和增量 JSONL 会话，按配置 ID 和时间区分。
- `plane_results/`：求解后的独立 JSON 配置与文本报告。
- `test_plane_math.py`：不连接设备的数学和安全边界测试。

最终配置至少包含：配置 ID、版本、toolcoord2、图像宽高、参考拍照位姿、允许姿态误差、H、局部平面参数、拟合指标、中心独立检查、原始会话路径和创建时间。

## 7. 异常与防误用

- 少于规定点数、点共线、重复像素、重复 TCP、非有限数值或图像尺寸变化：拒绝求解。
- 外圈八点拟合残差或中心独立检查超门限：保留数据并要求检查点选对应关系、A4 是否移动和 TCP 是否对准，不自动删除异常点。
- 当前 RPY 与配置不一致：拒绝输出定位结果；使用旋转矩阵计算角度差，避免 ±180° 跳变误判。
- 配置 ID 与现场作业面不一致：工具明确要求显式选择，不根据高度猜测。
- 会话恢复时校验配置 ID、参考图像和点编号，禁止把不同平面的数据拼接。
- 结果文件只用于静态验证；不含“已允许抓取”的标志。
- 所有设备脚本不包含运动、夹爪或底盘命令，设备连接失败时不写出可用配置。

## 8. 测试与验收

### 离线测试

1. 已知 H 和任意参考 RPY 的合成数据能恢复目标 XY。
2. 当前拍照 TCP 平移改变后，仍能正确转换到当前基座坐标。
3. 仓库与加工区不同 RPY 的配置不会混用，±180° 表示变化不会误报。
4. 加入小噪声时报告合理残差；共线、重复、缺点和错误尺寸均被拒绝。
5. 中心点不参与初始拟合，独立检查确实使用外圈八点结果。
6. 会话逐步保存和恢复不会丢失点顺序或混入其他配置。
7. 数学测试无需 RealSense、机械臂或运动命令即可运行。

### 现场静态验收

- 三个配置分别采集、分别生成，无交叉覆盖。
- 每个替代平面完成额外独立点静态 XY 验证，记录误差而不只看拟合 RMS。
- 在同一平面改变当前标准拍照 TCP 的平移但保持规定相对几何，验证相对映射的可复用性。
- 未通过现场静态验证前，不接自动运动。
- 真实仓库、加工区的最终验收仍需现场标准拍照位恢复、独立 Z 示教、高位空跑和安全验证，本阶段不提前宣称完成。

## 9. 后续集成边界

- YOLO 后续只需向静态定位模块提供工件中心像素及配置 ID。
- 传感器接口后续只负责槽位状态、选槽和结果校验，不参与平面映射。
- 车上取放和成品槽位放置后续读取独立示教轨迹，不依赖这三套视觉配置。
- 实际任务状态机、加工完成握手和通信协议在各自接口明确后单独设计，不在本阶段预埋无效实现。
